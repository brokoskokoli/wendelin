# WP89 Todoist und Google Tasks
> Stand: gültig

Vorbereitung: Emulator `Wendelin_AOSP_35` (serial `emulator-xxxx`) mit Netz. Todoist-Testkonto und persönlicher API-Token (Todoist → Einstellungen → Integrationen → Entwickler); Token nie in Chat oder Log einfügen, nur ins Feld der Einrichtungsseite.

## Todoist (WP89a)
- [ ] **WP89.1 Einrichtung.** Einstellungen → Integrationen → **Todoist**: „Token fehlt“, Einrichten öffnet die Seite. Falschen Token eingeben, **Verbinden**: Fehlermeldung (Token abgelehnt), nichts gespeichert. Richtigen Token: Karte „Aktiv“/in Ordnung, Feld verschwindet, der Token wird nie wieder angezeigt.
- [ ] **WP89.2 Anlegen.** „Trag Zahnarzt anrufen morgen um 9 Uhr bei Todoist ein.“ *Erwartet:* Bestätigung (write), danach Aufgabe im Eingang mit Fälligkeit morgen 09:00; in der Todoist-App sichtbar. Rückgängig löscht sie wieder.
- [ ] **WP89.3 Projekt und Priorität.** „Leg im Projekt Arbeit eine dringende Aufgabe Bericht schreiben an, fällig am Freitag.“ *Erwartet:* Aufgabe im Projekt Arbeit, Priorität p1. Unbekanntes Projekt: Fehlermeldung mit den vorhandenen Projekten.
- [ ] **WP89.4 Anzeigen.** „Was steht heute bei Todoist an?“ und „Was ist überfällig?“ *Erwartet:* passende Aufgaben, sortiert nach Datum, Zeit, Priorität. Ein Projekt mit mehr als 200 Aufgaben (falls vorhanden) wird vollständig gelesen.
- [ ] **WP89.5 Abhaken.** „Hak Zahnarzt bei Todoist ab.“ *Erwartet:* Aufgabe erledigt (in der App verschwunden), Rückgängig öffnet sie wieder. Wiederkehrende Aufgabe rückt zum nächsten Termin. Zwei ähnliche Titel: Rückfrage.
- [ ] **WP89.6 Fehlerfälle.** Flugmodus an: Meldung „nicht erreichbar … später erneut versuchen“, Integration bleibt aktiv. Token in Todoist widerrufen: nächster Aufruf pausiert die Integration (Zustand „Fehler“), „Erneut versuchen“ nach neuem Token (Seite) stellt sie wieder her.
- [ ] **WP89.7 Datenschutz.** Einstellungen → Protokoll/Export und Debug-Log. *Erwartet:* weder Token noch Aufgabentitel im Log; der Token steht nicht im Export.
- [ ] **WP89.8 Trennen.** Todoist → Trennen: Token weg, Integration wieder „Token fehlt“.

Emulator (E2E-Agent): Unit-Tests decken HTTP (aufgezeichnete Antworten), Tools und Fehlerzustand ab; offen sind die Punkte oben mit echtem Konto. Der Live-Test des Pakets läuft mit `set -a; . ~/.wendelin-live.env; set +a; cd packages/wendelin_integrations && dart test -t live --run-skipped test/todoist/todoist_live_test.dart` (nur mit `TODOIST_API_TOKEN`).

## Google Tasks (WP89b)
Vorbereitung: Google-Cloud-Projekt mit aktivierter Tasks API, OAuth-Client Typ „Desktop“, eigenes Konto als Testnutzer (Anleitung steht auf der Einrichtungsseite). Der Emulator braucht einen Browser (Chrome/WebView-Browser im Image), sonst „Es ist kein Browser installiert“. Client-ID und Secret nur ins Feld tippen, nie in Chat oder Log.

- [ ] **WP89.9 Einrichtung und Anmeldung.** Einstellungen → Integrationen → **Google Tasks**: „Google-Anmeldung fehlt“, Einrichten zeigt Anleitung und zwei Felder. Leer absenden: Hinweis. Mit Client-ID/Secret **Bei Google anmelden**: Browser öffnet Googles Seite (Warnung „nicht verifizierte App“ → Weiter, Aufgaben erlauben), danach zeigt der Browser „Fertig“; zurück in Wendelin ist die Integration aktiv, die Felder sind weg und kommen nie wieder.
- [ ] **WP89.10 Abbruch und Fehler.** Anmelden und im Browser „Abbrechen/Ablehnen“: Meldung „Anmeldung abgebrochen: Zugriff nicht erlaubt“. Im Browser ohne Antwort zurück in die App und **Abbrechen** tippen: „Anmeldung abgebrochen.“; die Seite http://127.0.0.1:<Port>/… ist danach nicht mehr erreichbar. Falsches Secret: Meldung „Google lehnt Client-ID oder Client-Secret ab“, nichts gespeichert.
- [ ] **WP89.11 Anlegen.** „Trag Zahnarzt anrufen morgen bei Google Tasks ein.“ *Erwartet:* Bestätigung (write), Aufgabe in „Meine Aufgaben“ mit Datum morgen (ohne Uhrzeit); in der Google-Tasks-App sichtbar. Mit Uhrzeit („morgen um 9 Uhr“): Antwort vermerkt, dass nur das Datum gespeichert wird. Rückgängig löscht sie.
- [ ] **WP89.12 Liste, Anzeigen, Abhaken.** „Leg in der Liste Arbeit … an“ (zweite Liste anlegen); „Was steht heute bei Google Tasks an?“, „Was ist überfällig?“; „Hak Zahnarzt bei Google Tasks ab.“ *Erwartet:* passende Aufgaben nach Datum sortiert; abgehakt verschwindet in der App, Rückgängig öffnet wieder. Zwei ähnliche Titel: Rückfrage.
- [ ] **WP89.13 Token-Erneuerung und Ablauf.** Eine Stunde warten (oder App neu starten) und erneut eine Aufgabe anlegen: funktioniert ohne neue Anmeldung. Zugriff unter myaccount.google.com/permissions entziehen: nächster Aufruf pausiert die Integration („Fehler“, Hinweis auf Neuanmeldung); danach ist das Anmeldeformular wieder da (Client-Felder neu eintragen).
- [ ] **WP89.14 Datenschutz.** Debug-Log und Export. *Erwartet:* weder Token, Client-ID, Client-Secret noch Aufgabentitel; Schlüssel `gtasks.*` nur im sicheren Speicher.
- [ ] **WP89.15 Abmelden.** Abmelden bestätigen: Zugriff in den Google-Berechtigungen ist widerrufen, alle `gtasks.*`-Geheimnisse sind weg, Integration wieder „Anmeldung fehlt“.

Emulator (E2E-Agent): Unit-Tests decken HTTP (synthetische Antworten), Token-Erneuerung, Login-Fälle (echter lokaler Server) und Tools ab; offen sind die Punkte oben mit echtem Konto. Der Live-Test läuft mit `set -a; . ~/.wendelin-live.env; set +a; cd packages/wendelin_integrations && dart test -t live --run-skipped test/google_tasks/google_tasks_live_test.dart` (nur mit `GOOGLE_TASKS_CLIENT_ID`, `GOOGLE_TASKS_CLIENT_SECRET`, `GOOGLE_TASKS_REFRESH_TOKEN`). Kotlin: `AuthChannel.open` hat keinen eigenen Unit-Test (Weg: WP89.9).

Automatisiert (Emulator, `cd app && ../tool/e2e_android.sh integration_test/wp89_tasks_e2e_test.dart`, grün auf emulator-5554): Todoist 401/gültig und Tools add/list/complete mit Undo; Google Tasks Anleitung, Erfolg, falscher `state`, Verlassen während des Logins (Empfänger zu, nichts gespeichert) und der echte Loopback-Server (falscher `state` → 400). Echtes Konto und Browser bleiben bei WP89.9 bis WP89.15.
