# WP160 – Stufe je Geräteart, Sprechererkennung-Diagnose, Stufen für MCP/HTTP-Tools (Gerätetest)

Logik deckt `packages/wendelin_integrations/test/home_assistant/` (Art-Stufen), `app/test/settings/ha_kind_level_test.dart` und die Sprecher-Tests (`speaker_test.dart`, `voice_pipeline_speaker_test.dart`). Offen für den Gerätetest (Emulator mit Fake-HA oder echtes HA; Sprecherteil nur auf dem Handy). Geräte sind hier nur Beispiele: nimm ein Licht, ein Rollo, ein Garagentor und ein Schloss aus der eigenen Installation.

- [ ] **(a) Licht-Art A:** Einstellungen → Integrationen → Home Assistant → „Stufe je Geräteart“: Licht auf A. Gerät sperren, fremde oder keine Stimme, „Licht an“. *Erwartet:* schaltet ohne Entsperren. Das Schloss bleibt gesperrt weiter nie schaltbar („Entsperren nötig“, nichts läuft, auch mit eigener Stimme). Danach Licht auf „Standard“ zurück.
- [ ] **(b) Art Rollos A lockert das Garagentor nicht:** Rollo-Art auf A (Hinweis bestätigen). *Erwartet:* ein echtes Rollo läuft entsperrt ohne Rückfrage, gesperrt ebenfalls; das Garagentor (Klasse garage/door) fragt weiter nach, in der Gerätezeile steht keine „von Geräteart“-Stufe. Danach zurück auf „Standard“.
- [ ] **(c) Eigene Gerätestufe schlägt die Art:** Licht-Art auf A, ein einzelnes Licht auf Stufe C stellen. *Erwartet:* gesperrt ohne Stimme „Entsperren nötig“ für dieses Licht, andere Lichter laufen; die Zeile zeigt „Stufe C“ ohne „von Geräteart“. „Standard wiederherstellen“ am Gerät → wieder die Art-Stufe A.
- [ ] **(d) Sprechererkennung (Logzeilen):** Einstellungen → Sprechererkennung an, Profil löschen und neu einlernen (5 Sätze, ruhig, normaler Abstand). Danach „Wer bin ich?“ fragen; dann Gerät sperren, Licht auf B, „Licht an“ per Weckwort. Entwicklermodus-Log auswerten:
  - `model-load kind=speaker model=speaker-campplus ms=…` einmal je Start (fehlt es, wurde das Modell nicht geladen; Ladezeit über 3000 ms heißt: erste Anfrage gilt als fremd).
  - `speaker-enroll samples=… thr=… clamped=… scores=min/max`: je Einlernen eine Zeile; `clamped=true` oder ein kleines min (unter etwa 0,45) heißt inhomogene Sätze, neu einlernen.
  - `speaker result=known|unknown reason=… best=… thr=… second=… audioMs=… ms=… profiles=…` je Anfrage. *Erwartet bei eigener Stimme:* `known`, `best` größer als `thr`. Bei `unknown`: `tooShort` (audioMs unter 1000), `belowThreshold` (best unter thr: Abstand/Pegel/Klang anders als beim Einlernen), `ambiguous` (second nahe an best), `failed` mit `error=…` (Modell fehlt oder Fehler), `timeout`. *Festhalten:* Zeilen (nur Zahlen) mit Entfernung zum Mikro und Situation (Weckwort, Overlay, getippt-gesperrt), pro Fall drei bis fünf Versuche, für die Auswertung der Erkennungsrate.
  - *Nachmessung Schwelle (Obergrenze 0,50):* `thr` darf nie über 0,50 liegen (auch bei altem Profil ohne Neu-Einlernen). Je Anfrage `best` und `thr` notieren (mindestens 10 Anfragen eigene Stimme, Abstand normal und etwa 1 m): erwartet überwiegend `known`; bleiben Anfragen zwischen 0,45 und 0,50 `unknown`, Scores melden. Dazu, wenn möglich, eine fremde Person sprechen lassen (erwartet `unknown`, `best` deutlich unter `thr`); jede Falscherkennung melden. Schlägt das Einlernen fehl, steht `speaker-enroll-failed reason=…` im Log.
  - Lichtschalten gesperrt mit Licht auf B klappt nur bei `result=known`; bei `unknown` kommt „Entsperren nötig“.
- [ ] **(e) MCP-/HTTP-Tool Stufe wählen:** Einstellungen → Integrationen → ein MCP-Server → Tool-Blatt: Auswahl A–D mit „Details“ sichtbar, Standard und „Standard wiederherstellen“. Ein Tool auf A: läuft ohne Rückfrage (entsperrt, und gesperrt ohne Entsperren); auf D: fragt nach. Ebenso ein HTTP-Tool im Editor (Abschnitt „Ausführung“): Stufe wählen, speichern, erneut öffnen (Wahl bleibt), umbenennen (Stufe bleibt), löschen. Bei „Alle Tools bestätigen“ am Server erscheint keine Auswahl.

Hinweis: Art- und Tool-Stufen sind Nutzerentscheidungen; alle Tests danach wieder auf „Standard“ zurückstellen.
