# WP120 Antwortzeit und Vorlesepausen

Voraussetzung: Xiaomi 15T Pro, Debug- oder Release-APK mit WP120, Sherpa-Stimme installiert, Gesprächsmodus nach Bedarf. Die Zeitleiste jeder Sprachanfrage steht als eine Zeile im Log (nur Zahlen, kein Text, Zeiten in ms ab Sprachende):

```
adb logcat -c
# ... Anfragen sprechen ...
adb logcat -d -s flutter | grep "Wendelin/voice: latency" > latency.txt
dart run tool/latency_report.dart latency.txt   # Tabelle p50/p90 je Abschnitt
```

Felder: `stt`, `m<i>_req/first/done` (Modellaufruf i), `tts1` (erster Satz an die Sprachausgabe), `syn_end`, `audio_first` (erster Ton), `audio_last`, `s<i>_syn` (Synthesezeit), `s<i>_gap` (Pause vor Satz i). Abgeleitet im Skript: `audio_first-stt`, `m1_done-m1_req`.

- [ ] **Zehn typische Befehle**, je einmal gesprochen, Sherpa-Stimme: (1) „Wie spät ist es?“ (2) „Schalte die Taschenlampe an.“ (3) „Stell einen Timer auf fünf Minuten.“ (4) „Wie wird das Wetter morgen?“ (5) „Was steht heute im Kalender?“ (6) „Erzähl mir einen kurzen Witz.“ (7) „Erkläre mir in drei Sätzen, wie ein Kühlschrank funktioniert.“ (8) „Wecker auf sieben Uhr morgens.“ (9) „Schreibe Milch auf die Einkaufsliste.“ (10) „Wie heißt die Hauptstadt von Australien?“ Auswerten: Tabelle merken (Vorher/Nachher gegen die Zahlen aus WP120-Messung). *Erwartet*: je Anfrage genau eine `latency`-Zeile, `audio_first-stt` p50 sinkt gegenüber dem Stand ohne WP120 (frühe Teilung des ersten Satzes nach sechs Wörtern).
- [ ] **Pausen zwischen Sätzen**: Bei Befehl 7 (mehrere Sätze) die `s<i>_gap`-Werte lesen und die Antwort anhören. *Erwartet*: kein hörbares Stocken zwischen den Sätzen (`s2_gap` klein, Ziel unter 300 ms), Satz 2 wird schon während Satz 1 synthetisiert.
- [ ] **Stopp verwirft Vorlauf**: Lange Antwort, nach dem ersten Satz „Stopp“ oder Antippen. *Erwartet*: sofort Ruhe, kein späterer Satz aus dem Vorlauf, nächste Anfrage normal.
- [ ] **Barge-in**: Lange Antwort, mittendrin „Wendelin“ und neue Frage. *Erwartet*: Antwort bricht ab, die Folgefrage wird beantwortet, kein alter Satz kommt dazwischen.
- [ ] **Kein Nutzertext im Log**: `grep latency latency.txt` enthält nur `k=Zahl`-Paare.

Emulator (E2E-Agent, im Ordner `app`): `WENDELIN_MODELS=~/wendelin-models tool/e2e_android.sh integration_test/voice_stop_word_e2e_test.dart integration_test/voice_barge_in_e2e_test.dart` (Stopp und Barge-in; das WAV für den Barge-in läuft erst nach `barge-listen on=true`, Schalter `waitForBargeListen` in der Overlay-Spezifikation). Offen, Lauf durch E2E-Agent.
