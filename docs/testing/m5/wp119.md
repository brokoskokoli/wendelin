# WP119 Nächster Wecker und Tools vorab

Voraussetzung: Emulator oder Xiaomi 15T Pro, Uhr-App vorhanden, mindestens 30 aktive Tools (viele Integrationen an, damit nur `tools__search` angeboten wird), Provider eingerichtet, Sprache Deutsch. Tool-Verlauf im Gespräch sichtbar (Tool-Zeilen).

- [ ] **Nächster Wecker**: In der Uhr-App zwei Wecker stellen (z. B. 07:00 und 09:30), dann „Wann klingelt mein nächster Wecker?“. *Erwartet*: Antwort nennt den nächsten Wecker mit Tag und Uhrzeit und sagt, dass nur dieser bekannt ist.
- [ ] **Kein Wecker**: Alle Wecker löschen, dieselbe Frage. *Erwartet*: „Es ist kein Wecker gestellt“, kein Fehler.
- [ ] **Wecker stellen ohne Suche**: „Stell mir einen Wecker um 7“. *Erwartet*: Im Verlauf steht `alarms__set_alarm`, **kein** vorheriges `tools__search`; ein Modellaufruf weniger.
- [ ] **Mehrsprachig**: Auf Französisch „Mets un réveil à sept heures“ und auf Englisch „Wake me up at 7“. *Erwartet*: ebenfalls ohne `tools__search`.
- [ ] **Unerkannte Anfrage**: „Ich brauche etwas Besonderes für Samstag“ (kein Themenwort). *Erwartet*: wie bisher, das Modell ruft zuerst `tools__search`.
- [ ] **Datenschutz**: Standard-Provider (kein TEE/lokal) und sensible Integration (z. B. Kontakte): „Ruf Anna an“. *Erwartet*: die sensiblen Tools werden nicht vorab mitgeschickt (Modell sieht sie nicht).

Emulator (E2E-Agent, falls frei): Wecker über `adb shell am start -a android.intent.action.SET_ALARM --ei android.intent.extra.alarm.HOUR 7 --ei android.intent.extra.alarm.MINUTES 0 --ez android.intent.extra.alarm.SKIP_UI true`, dann `adb shell dumpsys alarm | grep -i alarmclock` gegen die Antwort vergleichen. Kotlin: `cd app/android && ./gradlew testDebugUnitTest --tests app.wendelin.NextAlarmTest`.
