# WP108 Fehlerart bis zur Integrationskachel

Vorbereitung: Integrationen Bring!, Todoist, Google Tasks, Home Assistant und Spotify eingerichtet und eingeschaltet (mindestens zwei zum Stichprobenvergleich). Fehler erzeugen: Todoist-Token/Google-Refresh-Token/Spotify-Sitzung beim Dienst widerrufen; Home Assistant (Fake-HA aus `run_ha`) mit abgelehntem Token antworten lassen.

- [ ] **WP108.1 Zugriff verweigert.** Token widerrufen, danach einen Aufruf auslösen („Todoist: was steht an?“). *Erwartet:* Kachel in Einstellungen → Integrationen: Status „Fehler“, Zeile „<Dienst>: Zugang abgelehnt oder abgelaufen · pausiert“ (nicht der alte Mischtext), Knopf „Erneut versuchen“. Dieselbe Zeile auf der Dienstseite (Konto-Zeile).
- [ ] **WP108.2 Unerwartete Antwort.** Dienst liefert eine fremde Antwort (z. B. Fake-Server mit 200 und Müll bei Bring!). *Erwartet:* „<Dienst>: unerwartete Antwort · pausiert“.
- [ ] **WP108.3 Nicht erreichbar.** Dienst/Netz weg. *Erwartet:* Offline pausiert die Integration nicht; erst „Erneut versuchen“ zeigt „<Dienst> ist nicht erreichbar“ (Hinweistext, wie bisher).
- [ ] **WP108.4 Wiederherstellung.** Token erneuern, „Erneut versuchen“. *Erwartet:* Fehlerzeile weg, Status „Aktiv“; ein späterer anderer Fehler zeigt seinen eigenen Text, keinen alten.
- [ ] **WP108.5 Bring! abgelaufen.** Bring!-Refresh ungültig machen. *Erwartet:* weiter „Bring!: Anmeldung abgelaufen. Bitte neu anmelden.“ und „Erneut verbinden“ (WP107 unverändert).
- [ ] **WP108.6 Sprachen und Datenschutz.** Gerätesprache Englisch und Französisch. *Erwartet:* Zeilen übersetzt („refused or expired · paused“, „refusé ou expiré · en pause“); in keiner Zeile stehen Token, URLs oder Nutzerdaten.
