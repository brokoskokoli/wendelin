# WP203 MCP: Fehlermeldung des Servers zählt als Inhalt desselben Servers
> Stand: gültig

Voraussetzung: wie WP201. MCP-Server für Smart Home eingerichtet (`list_devices`, `set_device`), `set_device` in der Tool-Ansicht auf „Ohne Nachfrage“ (Stufe A), „Alle Tools bestätigen“ des Servers aus, Websuche an.

- [ ] **Falscher Name, dann richtiger**: neue Unterhaltung, Gerät mit einem Namen ansprechen, den der Server nicht kennt (z. B. „Schalte das Licht an“). *Erwartet*: der erste `set_device`-Aufruf meldet „Gerät nicht gefunden“, der zweite mit dem richtigen Namen läuft **ohne** Karte; die Lampe schaltet (in v0.1.9-rc1 kam hier eine Karte).
- [ ] **Fehler eines anderen Servers**: Tool eines zweiten MCP-Servers liefert einen Fehler, danach `set_device`. *Erwartet*: Karte mit Grund „andere Quelle“.
- [ ] **Server nicht erreichbar**: Server stoppen bzw. Netz trennen, „Schalte die Lampe an“ (scheitert mit Zeitüberschreitung/Verbindungsfehler), Server wieder erreichbar machen, im selben Gespräch „Schalte die Lampe an“. *Erwartet*: Karte mit Grund (der Fehler kam nicht vom Server). „Ja“ führt aus.
- [ ] **Nach Websuche bleibt die Nachfrage**: neue Unterhaltung, Websuche, dann falscher Gerätename, dann richtiger. *Erwartet*: Karte mit Grund.
- [ ] **Fortsetzung**: Ablauf „Falscher Name“ bis nach der Fehlermeldung, App beenden und neu starten, Gespräch fortsetzen, „Schalte die Lampe an“. *Erwartet*: ohne Karte.

## Nicht per Gerät prüfbar
Gefälschter Fehler-Umschlag im Text eines Client-Fehlers (fragt), alter Verlauf ohne das neue Feld (fragt) und Sitzungssperre mit roter TEE-Quittung (bleibt gesperrt): abgedeckt durch `app/test/agent/same_server_origin_test.dart`, die Core-Tests zu `ToolResultBlock` und `packages/wendelin_tools/test/policy/same_server_test.dart`.
