# WP148 – Entwicklermodus (Gerätetest)
> Stand: gültig

Emulator `Wendelin_AOSP_35` (Debug-Build), Auswertung per `adb logcat -d | grep Wendelin/dev`. Es gibt keinen Integrationstest für die Oberfläche; der E2E-Agent führt das Szenario von Hand aus. Logik und Verdrahtung decken die Tests `app/test/dev/*.dart`, `app/test/platform/voice/whisper_stt_test.dart` und `packages/wendelin_voice/test/stt_confidence_gate_test.dart` ab.

- [ ] **Ein/Aus:** Einstellungen → App-Sprache, 10× auf „System“ tippen. *Erwartet:* ab dem 7. Tippen Hinweis „Noch N× tippen …“, beim 10. „Entwicklermodus an“; in den Einstellungen steht „Entwicklermodus an – erweitertes Logging“. 10× erneut: „Entwicklermodus aus“, Hinweis weg. App neu starten: Zustand bleibt.
- [ ] **Ohne Flag:** Eine Anfrage mit Werkzeug (z. B. „Schalte die Taschenlampe an“, getippt und gesprochen). *Erwartet:* `grep Wendelin/dev` leer.
- [ ] **Mit Flag (getippt):** Modus an, dieselbe Anfrage tippen. *Erwartet:* `tool-call tool=… args=…`, `tool-result … status=ok result=…`, `model-text`, keine doppelten Zeilen.
- [ ] **Mit Flag (gesprochen):** Anfrage per Mikrofon/WAV-Szenario. *Erwartet:* zusätzlich `stt-text text=…`; Werkzeugzeilen genau einmal; bei Zuruf nur des Weckworts `wake-strip`, bei unsicherer Erkennung `stt-reject`.
- [ ] **Ohne Neustart:** Overlay (Assistentengeste) bei laufender App öffnen, in der App den Modus umschalten, im Overlay die nächste Sprachanfrage stellen. *Erwartet:* Zeilen mit `engine=overlay` erscheinen bzw. verschwinden ohne Neustart.
- [ ] **Secrets:** Anfrage mit „Passwort ist …“ bzw. Werkzeugargument `password`. *Erwartet:* `***` bzw. geschwärzter Wert, nie der Klartext.
- [ ] **Bonus Hinweisbegriffe:** Sprache → Gesprächsmodus → Erweitert: Option nur bei an. Wert 1,5 setzen, Modus aus: Wert wirkt weiter (`stt-lang … hws=1.50`).
- Befehl für die vorhandenen Werkzeug-E2E-Läufe (Kontrolle, dass nichts ohne Flag loggt): `tool/e2e_android.sh integration_test/calendar_e2e_test.dart` (aus `app/`), danach `adb logcat -d | grep -c Wendelin/dev` = 0.
- [ ] **Tonaufnahmen (Modus an):** Weckwort sagen (auch ein Fehlalarm-Kandidat), Antwort abwarten, bei Wiedergabe unterbrechen. `adb -s <emulator> pull /sdcard/Android/data/app.wendelin/files/dev-audio ./dev-audio`, Dateien abspielen. *Erwartet:* `*_wake-cand.wav`, `*_wake-verify.wav`, `*_rec.wav` (bei Unterbrechung `*_barge-cand.wav`, `*_barge-verify.wav`); Dateinamen und Längen stimmen mit `adb logcat -d | grep "Wendelin/dev: audio"` (`file=`, `ms=`, Marken wie `wakeEndMs`, `speechStartMs`) überein, Marken liegen an den gehörten Stellen. Bekannte Grenze: Kandidat-Clips nach bestätigtem Weckwort sind kürzer als ±2 s (`postMs` nennt die echte Länge).
- [ ] **Tonaufnahmen ohne Flag:** Modus aus, dieselbe Szene. *Erwartet:* `dev-audio` leer oder fehlt, keine `audio`-Zeile. Sitzung nach dem Ausschalten (Overlay/Station schon offen): nichts Neues abgelegt.
- [ ] **Aufräumen:** Datei mit altem Datum (`adb shell touch -d '3 days ago' …`) ablegen, App neu starten. *Erwartet:* Datei ist weg.
