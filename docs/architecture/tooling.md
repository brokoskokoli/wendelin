# Werkzeug-Interna: CI-Jobs, Claude-Code-Hooks, Emulator

Technische Referenz zu `docs/ENGINEERING.md` (Abschnitte „Tests (Gate)“ und „Git“). Regeln stehen dort und in `AGENTS.md`; diese Datei nur bei Bedarf lesen.

## CI-Jobs

CI-Jobs: `scope` (Umfang aus `tool/ci_scope.sh --ci`), ein Ubuntu-Job je Paket (`dart run tool/gate.dart --only <paket>`: ohne globale Prüfungen und Werkzeug-Selbsttests; `wendelin_integrations` in 2 Shards `--shard=i/2`, die Abdeckung prüft `pkg-coverage` über beide, `tool/check_pkg_coverage.dart`), `global-checks` (`gate.dart --globals`: alle `check_*` und die Selbsttests einmal), `rust-checks` (Rust, `gate.dart --only native/attest`), `app-analyze`, `app-test` in 3 Shards ohne Goldens und `platform-sensitive` (Abdeckung von `app/lib/di` über alle Shards in `app-coverage`, `tool/check_app_coverage.dart`), `goldens` auf dem gepinnten `macos-15` (nur dort; Referenzbilder neu erzeugen mit dem Workflow `update-goldens`, Artefakt `goldens`), `kotlin-unit` und `apk` (main/PR, auf `wp/**` nur bei Änderungen an `app/android/**` oder `pubspec*`; K7-GMS-Prüfung). **Reine Doku-Läufe:** Ändert der Push nur Markdown (außer unter `lib/`, `test/`, `integration_test/`; Bezug ist die Merge-Basis mit origin/main, auf `main` der vorige Push), läuft nur der Job `docs-only` (`check_docs`), alle anderen Jobs entfallen. Ein Branch mit Code im Diff gegen die Merge-Basis bekommt deshalb immer den vollen Lauf, auch wenn der letzte Commit nur Doku ändert. Die Paketmatrix entsteht im Job `scope` aus `packages/` (plus `evals`). Alle Fremd-Actions sind per Commit-SHA gepinnt (Version im Kommentar), der Workflow hat nur `contents: read`. **Golden-Schutz:** pixelgenau ist er nur im lokalen macOS-Lauf (`--changed`, Goldens sind dort aufgenommen); in CI gilt die Toleranz 1 % Pixelanteil und höchstens 6000 Pixel (`app/test/support/golden_tolerance.dart`), dort fallen nur größere Änderungen auf. Caches: Flutter/pub, Cargo (`rust-cache`), Gradle. Keine Secrets, Live-Tests bleiben übersprungen.

## Merge nach main

- **`tool/merge_pr.sh <pr-nummer> --model "<Modell>"`** (bash, im Checkout auf `main`, kein Push): `git fetch`; PR über `gh pr view` (offen, Basis `main`, Kopf-Branch, Kopf-SHA, Titel), `origin/<kopf-branch>` muss der Kopf-SHA sein. CI-Beleg: der neueste Lauf des Workflows `gate` auf dem Kopf-SHA ist completed/success; enthält der Diff gegen origin/main Code (`tool/ci_scope.sh --classify`), darf er nicht nur aus dem Job `docs-only` bestehen. Danach `tool/check_commit_identity.sh origin/main..<kopf-sha>`, `main` auf origin/main (nur ohne lokale Commits), `git merge --no-ff` mit `Merge #<pr>: <titel>` und genau einem Trailer `Co-Authored-By: Claude <Modell> <noreply@anthropic.com>`; Identität und Trailer-Muster liest das Werkzeug aus `tool/check_commit_identity.sh` und prüft den Merge-Commit damit. Konflikt → `merge --abort`, Abbruch. Zum Schluss die Freigabe `<tree> <commit>` nach `<git-common-dir>/wendelin-merge-ok` und der Push-Befehl. Jeder Abbruch hinterlässt weder Merge-Commit noch Freigabe. Umgebung für Tests: `MERGE_PR_VIEW`, `MERGE_PR_CI`, `MERGE_PR_CI_MODE`, `MERGE_PR_NAME`/`MERGE_PR_EMAIL`, `MERGE_PR_REMOTE`. Selbsttests: `tool/src/merge_pr_self_test.dart`.
- **`tool/hooks/pre-push.sh`** (ohne Netzzugriff): Ein Commit auf `main` ist erlaubt, wenn er nur Doku ändert oder sein Tree in `wendelin-merge-ok` steht (dann auch die Commits, die er mitbringt). Zeilen ohne Commit gelten nicht; Freigaben, deren Commit (oder Tree) schon in origin/main liegt, räumt der nächste Push weg. Die Freigabe liegt im `git-common-dir`, nie im Repo. Weiter abgelehnt: ohne `WENDELIN_PUSH_MAIN=1`, Löschen, Rücksetzen/Force-Push, Merge `-s ours`, Code ohne Freigabe. Selbsttests: `tool/src/git_guards_self_test.dart`. Der Hook ist eine Leitplanke gegen versehentliche Pushes, keine Authentifizierung.

## Claude-Code-Hooks

- **Claude-Code-Hooks** in `.claude/settings.json`, Skripte (Python 3) in `tool/hooks/claude/`, Selbsttests `tool/src/claude_hooks_self_test.dart`. `bash_guard.py` (PreToolUse Bash) lehnt mit exit 2 ab: `--no-verify` (auch `commit -n`), `git push` auf main (Ketten, `env`/`export`, Quotes, `bash -c`/`eval`, `git -C`, `HEAD:main`, `+main`, voller Ref-Name, `--all`, `push` ohne Ziel auf main) ohne `WENDELIN_PUSH_MAIN=1`, `pkill`/`killall`, `git -c user.*`/`core.hooksPath`, `git config user.*` (schreibend), `GIT_AUTHOR_*`/`GIT_COMMITTER_*`-Zuweisungen. Erkannt werden auch Shell-Schlüsselwörter (`if`/`then`/`while`/`!`/`{` und Funktionskörper), Wrapper mit Optionswerten (`timeout`, `nice -n`, `sudo -u`, `nohup`, `xargs`, `find -exec`), abgekürzte Langoptionen (`--no-v…`) und das Ziel heads/main ohne refs-Präfix. Bekannte Restlücken, die `tool/hooks/pre-push.sh` abfängt: Befehle in `$(…)` innerhalb von Anführungszeichen, `… | bash`, Ziel aus einer Variablen (`$VAR`) oder aus stdin (`xargs`), nacktes `git push` nach `cd` in einen anderen Checkout; Heredoc-Inhalte werden übersprungen.

## Emulator-Sperre und -Autostart

- **Emulator-Sperre:** `tool/emulator_lock.sh` (von `tool/e2e_android.sh` eingebunden) legt je Serial `${TMPDIR}/wendelin-emulator-locks/<serial>.lock/` mit PID und WP an; belegt: sofort Abbruch „Emulator … belegt durch WPnn, PID …“, kein Warten; Freigabe per `trap` (auch bei Abbruch), verwaiste Sperren (PID tot, oder ohne `info` länger als eine Minute) werden atomar übernommen (Mutex `<serial>.lock.takeover`, der Verlierer bricht ab).

- **Emulator-Autostart:** `tool/emulator_boot.sh` (von `tool/e2e_android.sh` vor der Geräteauswahl eingebunden) startet `Wendelin_AOSP_35` headless (nohup, Log `${TMPDIR}/wendelin-emulator-<serial>.log`, Port aus `DEVICE=emulator-NNNN`, sonst 5554), wartet bis `sys.boot_completed` (`EMU_BOOT_TIMEOUT`, Standard 240 s) und beendet ihn in `cleanup` per `adb emu kill` vor der Freigabe der Emulator-Sperre; `E2E_KEEP_EMULATOR=1` lässt ihn laufen. Gleichzeitiger Start: Mutex `<serial>.start`, der zweite Lauf bricht sofort ab. Echte Geräte werden nie gestartet oder beendet (ein daneben verbundenes Gerät stört nicht, ohne `DEVICE` wird der Emulator gewählt). Selbsttest mit Fake-adb/-emulator: `tool/src/emulator_boot_self_test.dart`.
